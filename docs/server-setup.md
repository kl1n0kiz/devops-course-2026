# Конфигурация виртуальной машины devops-vm

## 1. Параметры машины

- Операционная система: Ubuntu Linux.
- Оперативная память: 1 GiB.
- Процессор: 2 ядра.
- Диск: 25 GiB (`/dev/vda`).
- Корневой раздел: LVM, 21,9 GiB, точка монтирования `/`.
- Имя хоста: `devops-vm.devops.local`.

## 2. Сетевые интерфейсы

- Интерфейс: `enp0s1`.
- IPv4-адрес: `192.168.64.2/24`.
- Адрес IPv6: `fd71:4cac:8f81:94bf:7486:80ff:fe5b:aa5/64`.
- Подключение к ВМ выполняется по её адресу в локальной сети.

## 3. Правило проброса портов

Проброс портов хостовой системы не используется. SSH-подключение выполняется напрямую:

- клиент: macOS;
- адрес ВМ: `192.168.64.2`;
- порт SSH гостевой системы: `2222`;
- команда подключения: `ssh devops`.

## 4. Учётные записи

| Учётная запись | Группы | Способ аутентификации |
|---|---|---|
| `devops` | `devops`, `sudo`, `users` | SSH-ключ, парольный вход отключён |
| `student` | `student`, `adm`, `cdrom`, `sudo`, `dip`, `plugdev`, `lxd` | локальная учётная запись |

## 5. Служба SSH

Файл конфигурации: `/etc/ssh/sshd_config` и дополнительные файлы `/etc/ssh/sshd_config.d/`.

Изменённые параметры:

| Параметр | Значение |
|---|---|
| `Port` | `2222` |
| `PermitRootLogin` | `no` |
| `PasswordAuthentication` | `no` |
| `PubkeyAuthentication` | `yes` |
| `MaxAuthTries` | `3` |
| `AllowUsers` | `devops` |

Доступ к серверу проверен с macOS командой `ssh devops`.

## 6. Правила межсетевого экрана

Используется UFW.

- Состояние: `active`.
- Политика по умолчанию для входящего трафика: `deny`.
- Политика по умолчанию для исходящего трафика: `allow`.
- Журналирование: включено, уровень `medium`.

Разрешённые правила:

| Порт | Протокол | Правило | Назначение |
|---|---|---|---|
| 80 | TCP | `ALLOW IN` | HTTP |
| 443 | TCP | `ALLOW IN` | HTTPS |
| 2222 | TCP | `LIMIT IN` | SSH с ограничением частоты попыток |

Правила действуют для IPv4 и IPv6.

## 7. Снимки состояния

- `01-clean-install` — чистая установка Ubuntu, до настройки сервисов.
- `03-ssh-hardened` — после настройки SSH, UFW и успешного запуска `scripts/audit.sh`.

## Проверка конфигурации

Скрипт `scripts/audit.sh` запускается на ВМ и проверяет:

1. запрет входа под `root`;
2. отключение парольной аутентификации;
3. нестандартный SSH-порт `2222`;
4. ограничение `MaxAuthTries = 3`;
5. активность UFW;
6. политику `deny` для входящего трафика.

Результат последнего запуска: `Пройдено: 6, не пройдено: 0`.

## 10. Ansible

**Расположение проекта.** Каталог `ansible/` в репозитории `devops-course-2026`, ветка `feature/ansible`. Запуск выполняется из каталога `ansible/`, где лежит `ansible.cfg`.

**Узлы.** Управляющий узел: MacBook Air (macOS, arm64) с ansible-core, коллекциями из `requirements.yml` и sshpass. Управляемый узел: VM `devops-vm` (UTM, Ubuntu Server 24.04 aarch64), адрес Host-only 192.168.64.2.

**Inventory и учётные записи.**
- `inventory/bootstrap.ini`: пользователь `student`, вход по паролю (только первый запуск).
- `inventory/prod.ini`: пользователь `devops`, вход по ключу `~/.ssh/devops_vm`, пароль не запрашивается.
- Пароли и закрытый ключ в репозиторий не входят.

**Роли и ответственность.**
- `base`: проверка ОС и архитектуры (aarch64), базовые пакеты, официальный репозиторий Docker (arm64), служба Docker.
- `ssh`: пользователь `devops`, публичный ключ, sudo NOPASSWD, hardening SSH (`00-ansible-hardening.conf`), UFW (22 и 80), handler Restart SSH.
- `nginx`: пакет Nginx, reverse proxy на 127.0.0.1:5000, отключение default site, handlers: `nginx -t`, затем reload.
- `app`: загрузка образа по тегу, контейнер, проверка `/health`.

**Приложение.**
- Образ GHCR: `ghcr.io/kl1n0kiz/devops-ci-app`.
- Полный SHA (тег): `1772892d9b59219241dd0e989f90fdd97aa8dec3`. Тег `latest` не используется.
- Контейнер `devops-ci-app`, порт 5000 публикуется только на 127.0.0.1; наружу доступ через Nginx на порту 80.
- Health endpoint: `/health`, ожидается `{"status":"ok"}`.
- Требование к GHCR: пакет публичный, доступен на чтение без аутентификации.

**Команды.**

```bash
cd ~/devops-course-2026/ansible
# первичный запуск (пароль student)
ansible-playbook -i inventory/bootstrap.ini site.yml --ask-pass --ask-become-pass
# повторные запуски (по ключу, ожидается changed=0)
ansible-playbook site.yml
# read-only аудит (ничего не меняет, ожидается changed=0)
ansible-playbook verify.yml
```
